# llm-prompting-coverage
 
Experiment materials for the paper **"The Effect of Prompting Strategies on the Code Coverage of LLM-Generated Unit Tests"** (Research Methods and Tools course, Astana IT University, 2026).
 
The repository contains the prompts, selected functions, generated test files, logs, scripts, and results of a controlled experiment that isolates **prompting strategy** (zero-shot, few-shot, chain-of-thought) as the only manipulated variable.
 
## Research question and hypotheses
 
- **RQ:** How does prompting strategy (zero-shot, few-shot, chain-of-thought) affect the code coverage of unit tests generated by a single LLM, when the model, programming language, and code under test are held constant?
- **H0:** There is no statistically significant difference in code coverage among the three strategies.
- **H1:** There is a statistically significant difference in code coverage among the three strategies.
## Results at a glance
 
| Strategy | Mean line coverage (%) | Median (%) | SD (%) | Min (%) | Max (%) | Suites passing all assertions |
|---|---|---|---|---|---|---|
| Zero-shot | 98.0 | 100 | 6.32 | 80 | 100 | 7 / 10 |
| Few-shot | 98.0 | 100 | 6.32 | 80 | 100 | 9 / 10 |
| Chain-of-thought | 98.8 | 100 | 3.79 | 88 | 100 | 5 / 10 |
 
- 27 of the 30 function-strategy combinations reached 100% line coverage (ceiling effect). Only `avoid_fifth` differed between strategies.
- Shapiro-Wilk on the paired differences rejected normality for comparisons involving chain-of-thought (W = 0.366, p < 0.001); the few-shot minus zero-shot differences were all identical.
- **Friedman test (primary):** chi-square(2) = 2.00, p = 0.368, Kendall's W = 0.10. **H0 was not rejected.**
- Repeated-measures ANOVA (check): F(2, 18) = 1.00, p = 0.3874.
- Exploratory Cochran's Q test on suites passing all assertions: Q(2) = 4.80, p = 0.091.
- Because the overall test was not significant, no pairwise follow-up comparisons were run.
## Design
 
| Item | Value |
|---|---|
| Design | Quantitative, within-subjects controlled experiment |
| Independent variable | Prompting strategy (3 levels) |
| Dependent variable | Line coverage (%) of the function under test |
| Model | `claude-sonnet-5-5` via the Anthropic Messages API (SDK 2.3.0) |
| max_tokens | 8000 |
| Sampling parameters | Not settable for this model and API version; API defaults used |
| Attempts | Up to 3 per combination; first valid attempt retained |
| Acceptance rule | Non-empty, not truncated by the token limit, extractable valid code, at least one `test_*` function |
| Test tools | pytest 9.1.1, coverage.py 7.16.2 |
| Functions | 10 Python functions from the decontaminated split of UnLeakedTestBench, stratified over 5 function types |
 
An earlier run with `max_tokens=1500` produced mostly unusable outputs; the limit was raised to 8000 and the whole experiment was rerun. Only the rerun is reported.

## Data files
 
**`results.csv`** columns: `function_name`, `strategy`, `coverage_percent`, `lines_covered`, `lines_total`, `test_status`, `notes`. `test_status` is `SUCCESS` when all assertions passed and `TEST_FAILURES` when some assertions failed (coverage is still recorded).
 
**`generation_log.csv`** columns: `timestamp`, `function_name`, `strategy`, `attempt`, `stop_reason`, `input_tokens`, `output_tokens`, `status`.
 
## Setup
 
Python version used: `3.14.6`
 
```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python3 -m pip install -r requirements.txt
```
 
## Reproducing the statistical analysis (no API key needed)
 
```bash
python3 analysis.py
```
 
`analysis.py` reads `results.csv` and prints the descriptive statistics, the Shapiro-Wilk checks, the Friedman test, the repeated-measures ANOVA, and the Cochran's Q test reported in the paper.
 
## Reproducing the full experiment (API key and cost required)
 
1. Create a `.env` file in the repository root (it is git-ignored) containing `ANTHROPIC_API_KEY=your_key_here`.
2. Run `python3 experiment_runner.py` to generate the 30 test files and `generation_log.csv`.
3. Run `python3 measure_coverage.py` to execute the tests under coverage and write `results.csv`.
4. Run `python3 analysis.py`.
**Reproducibility note:** sampling parameters could not be set, so regenerating the tests will not give identical outputs and coverage values may differ. The stored test files, logs, and `results.csv` are the exact artefacts behind the reported results.
